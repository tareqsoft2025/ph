# ph — نظام إدارة المطعم

نظام متكامل لإدارة المطعم: نقطة بيع، طاولات، شاشة مطبخ لحظية، دفع وفواتير، مخزون بالوصفات، ورديات، حجوزات، عملاء، وتقارير — مع تطبيق أندرويد (APK) مرتبط بنفس الخادم.

```
┌──────────────────────┐        Wi-Fi / الشبكة المحلية        ┌──────────────────────────┐
│  الخادم (Node.js)     │ ◄──────── REST API + WebSocket ─────► │ تطبيق أندرويد (APK)       │
│  backend/            │                                       │ للنادل / الكاشير / المطبخ │
│  قاعدة بيانات SQLite  │ ◄──────────── المتصفح ───────────────► │ أو أي متصفح على الشبكة    │
└──────────────────────┘                                       └──────────────────────────┘
```

## 🌐 النسخة التجريبية على الإنترنت

**https://tareqsoft2025.github.io/ph/**

تعمل بالكامل داخل المتصفح بدون خادم: قاعدة البيانات SQLite تعمل عبر WebAssembly والبيانات محفوظة على الجهاز نفسه فقط. افتح أكثر من تبويب (مثلاً الكاشير في تبويب والمطبخ في آخر) لترى التحديث بينها. للتشغيل الفعلي في المطعم استخدم الخادم كما في الأسفل.

تحديث النسخة التجريبية بعد أي تعديل على الواجهة أو الخادم:

```bash
cd web && npm run deploy:demo
```

ثم ارفع التغييرات في مجلد `docs/`. تُنشر الصفحة من الفرع `main`، المجلد `/docs` (الإعداد في **Settings → Pages**).

| المجلد | المحتوى |
|---|---|
| `backend/` | الخادم: Node.js + Express + Socket.io + SQLite (مدمجة في Node، بدون تثبيت قاعدة بيانات) |
| `web/` | الواجهة: React + Vite، عربية بالكامل (RTL)، تعمل على الشاشات الكبيرة والجوال (`web/src/demo/`: بدائل المتصفح للنسخة التجريبية) |
| `web/android/` | مشروع أندرويد (Capacitor) يغلّف الواجهة في تطبيق APK |
| `apk/` | تطبيق الأندرويد الجاهز للتثبيت `restaurant-app.apk` و`version.json` (ونسخة منه في `docs/apk/` للنسخة التجريبية) |
| `docs/` | تحليل النظام وتوثيق الـ API، والنسخة التجريبية المبنية لـ GitHub Pages |

## التشغيل السريع

المتطلبات: **Node.js 22.13 أو أحدث**.

```bash
cd web && npm install && npm run build
```

```bash
cd backend && npm install && npm start
```

سيطبع الخادم عنوانه على الشبكة، مثل `http://192.168.1.10:3000`. افتحه من أي متصفح على نفس الشبكة.

### الحسابات التجريبية

| الدور | اسم المستخدم | كلمة المرور |
|---|---|---|
| المدير العام | `admin` | `admin123` |
| مدير الفرع | `manager` | `1234` |
| كاشير | `cashier` | `1234` |
| نادل | `waiter` | `1234` |
| المطبخ | `kitchen` | `1234` |

> غيّر كلمات المرور من صفحة **المستخدمون** وعيّن متغير البيئة `JWT_SECRET` قبل الاستخدام الفعلي.

## تطبيق الأندرويد

1. نزّل التطبيق بالضغط على زر **تطبيق الأندرويد** أعلى الصفحة (أو من صفحة الدخول)، أو من المجلد `apk/restaurant-app.apk` في المشروع، ثم ثبّته على الجوال أو التابلت (فعّل "التثبيت من مصادر غير معروفة").
2. تأكد أن الجهاز على **نفس شبكة الـ Wi-Fi** التي عليها الخادم.
3. عند أول فتح أدخل عنوان الخادم (مثل `http://192.168.1.10:3000`) ثم سجّل الدخول.

يعرض التطبيق الشاشات حسب دور المستخدم: النادل يرى الطاولات ونقطة البيع، والمطبخ يرى شاشة الطلبات، وهكذا.

### إصدار تحديث (الواجهة والتطبيق معاً)

التطبيق والنظام مرتبطان: أي تعديل يتطلب إصداراً جديداً يحدّث الاثنين. بعد أي تعديل شغّل:

```bash
bash scripts/release.sh
```

يرفع رقم الإصدار، ويبني الواجهة والنسخة التجريبية وتطبيق الأندرويد، ويضع الـ APK في `apk/` و`docs/apk/`. يظهر زر التنزيل في الواجهة برقم الإصدار وحجمه، ويخدمه الخادم من `/apk/restaurant-app.apk`.

### بناء الـ APK بنفسك

يحتاج JDK 21 و Android SDK (المنصة 36):

```bash
cd web && npm run apk
```

الناتج: `web/android/app/build/outputs/apk/release/app-release.apk`

كما يبني GitHub Actions الملف تلقائياً عند كل تعديل (`.github/workflows/android.yml`) ويرفعه كـ Artifact.

**التوقيع:** بدون إعداد يُوقَّع الإصدار بمفتاح تطوير. للنشر الرسمي أنشئ مفتاحاً خاصاً:

```bash
keytool -genkey -v -keystore release.jks -keyalg RSA -keysize 2048 -validity 10000 -alias restaurant
```

ثم أنشئ `web/android/keystore.properties` (لا يُرفع للمستودع):

```properties
storeFile=/path/to/release.jks
storePassword=...
keyAlias=restaurant
keyPassword=...
```

## التصميم

- **الخطوط:** Alexandria للعناوين و IBM Plex Sans Arabic للنصوص (رخصة OFL مجانية)، مضمّنة داخل التطبيق فتعمل دون إنترنت.
- **الأيقونات:** مكتبة Lucide.
- **الألوان:** زمرّدي دافئ مع لمسة نحاسية، مع وضع ليلي تلقائي.
- كل الألوان والمقاسات معرّفة كمتغيرات في أعلى `web/src/styles.css`.

> لاستخدام خط ثمانية: ترخيصه الحالي للاستخدام الشخصي فقط ولا يسمح بنشره على موقع أو داخل تطبيق. إذا حصلت على ترخيص تجاري من ثمانية، ضع ملفات الخط في المشروع وغيّر المتغيرين `--font-display` و `--font-body` في `web/src/styles.css`.

## الوحدات

- **نقطة البيع:** صالة / سفري / توصيل، إضافات وملاحظات لكل صنف، خصم بنسبة أو مبلغ، دفع نقدي/بطاقة/محفظة مع تقسيم الدفع وحساب الباقي، طباعة فاتورة حرارية 80مم.
- **الطاولات:** خريطة حسب المنطقة بحالات (فارغة/مشغولة/محجوزة)، مدة الجلوس، تنبيه الأصناف الجاهزة، نقل الطلب بين الطاولات.
- **قائمة الطعام:** فئات وأصناف وأسعار وإضافات، إيقاف صنف عند نفاده، وصفة لكل صنف مع حساب التكلفة وهامش الربح.
- **المخزون:** مواد خام بوحدات مختلفة، خصم تلقائي عند البيع حسب الوصفات، استلام بضاعة (متوسط تكلفة مرجّح)، تالف، جرد، تنبيه الحد الأدنى.
- **الورديات:** فتح وإغلاق مع جرد الصندوق وحساب الفرق.
- **الحجوزات والعملاء:** حجز طاولة بالموعد، سجل العملاء ونقاط الولاء.
- **التقارير:** المبيعات، الضريبة، الخصومات، تكلفة المبيعات ومجمل الربح، الأكثر مبيعاً، حسب الفئة/الساعة/اليوم/الموظف/طريقة الدفع، الهدر، النواقص.
- **كود الطلب وتسلسل العملية:**
  - لكل طلب كود ثابت (مثل `ORD-261116-0007`) يظهر في نقطة البيع والطلبات والطاولات والمطبخ والفاتورة.
  - "تفاصيل العملية" تعرض شريط المراحل (الإنشاء، المطبخ، التحضير، جاهز، التقديم، الدفع)، والتسلسل الكامل لكل خطوة: من نفّذها ومتى.
- **بيانات العميل الإلزامية:**
  - الصالة: الطاولة وعدد الأشخاص واسم العميل وجواله.
  - السفري: الاسم والجوال.
  - التوصيل: الاسم والجوال والعنوان.
- **الإشعارات:**
  - جرس بعدّاد غير المقروء، ولوحة إشعارات، وتنبيهات منبثقة بصوت واهتزاز.
  - إشعارات المتصفح أو الجهاز، وإشعارات أصلية في تطبيق الأندرويد.
  - تصل عند: طلب جديد للمطبخ، والطلب جاهز للنادل الذي أنشأه (وللكاشير في السفري والتوصيل)، وطلب إجازة للمدير، وقرار الإجازة للموظف، ونقص المخزون.
- **شاشة المطبخ:**
  - ثلاثة أعمدة: جديدة، قيد التحضير، جاهزة للتقديم، تضم طلبات كل الطاولات.
  - تعرض كل تذكرة كود الطلب ومن أرسله، مع مؤقت يتغير لونه حسب التأخير.
  - ملخص الكميات المطلوب تحضيرها، ووضع ملء الشاشة.
  - **الإشعارات الفورية (Firebase):** تصل لتطبيق الأندرويد حتى وهو مغلق، بعد إعداد مشروع Firebase. الخطوات في [docs/FIREBASE.md](docs/FIREBASE.md).
- **الكاشير:**
  - صفحة خاصة تعرض الطلبات بانتظار الدفع (من طلب الحساب أولاً) مع تفاصيل كل طلب، والتحصيل والخصم والفاتورة المبدئية، وملخص الوردية وتحصيلات اليوم.
  - الكاشير لا ينشئ طلبات افتراضياً. النادل يضغط "طلب الحساب" فيصل إشعار للكاشير.
- **إغلاق الطلب بعد الدفع:** طلب الصالة يُغلق، وتُعلَّم أصنافه كمقدّمة، وتُحرَّر الطاولة، ويختفي من شاشة المطبخ.
- **الصلاحيات القابلة للتخصيص:**
  - 26 صلاحية مجمّعة، يحدّد المدير العام منها ما يملكه كل دور (مدير الفرع، الكاشير، النادل، المطبخ).
  - تُطبّق فوراً على كل الأجهزة، مع إمكانية الإعادة للافتراضي.
- **سجل الحركات:** كل عملية في النظام بوصف عربي واضح: من نفّذها، ومتى، وعلى أي طلب. مع فلترة بالمستخدم ونوع العملية والتاريخ والبحث.
- **شاشة الطلب من الطاولة:**
  - لا توجد شاشة طلب عامة: الطلب يُفتح من الطاولة (`#/pos?type=dine_in&table=11`)، أو من زر "طلب سفري" و"طلب توصيل" في صفحة الطاولات.
  - في أعلى الشاشة لوحة تفاعلية للطاولة: رسم للطاولة والكراسي حسب عدد المقاعد، والنقر على الكراسي يحدد عدد الأشخاص، ومع كل شخص يظهر طبق.
  - تعرض اللوحة اسم الطاولة ومنطقتها وحالتها، ومدة الجلوس، وكود الطلب، والعميل، وإجمالي الطاولة.
- **الحضور الآمن:**
  - التسجيل من التطبيق أو المتصفح، وفقط من **مواقع العمل** المحددة على الخريطة مع نصف قطر مسموح.
  - لكل موظف إعداداته: سماحية التأخير، والمواقع المسموحة أو "أي مكان"، وأقصى وقت للحضور قبل الدوام، وربط الحساب بجهاز واحد.
  - إجراءات منع التحايل:
    - الوقت من الخادم دائماً.
    - رمز تحدٍّ لمرة واحدة صالح دقيقتين، فلا يمكن إعادة إرسال طلب قديم.
    - كشف الموقع الوهمي والمحاكي والأجهزة المكسورة الحماية (Root) في تطبيق الأندرويد.
    - رفض الموقع ضعيف الدقة أو القديم.
    - ربط الجهاز لمنع التسجيل من جوال زميل، وحد لعدد المحاولات.
    - تسجيل كل محاولة مرفوضة، وتنبيه المدير بالمحاولات المشبوهة.
  - **تقارير الحضور:**
    - نسبة الحضور، والغياب، والتأخير، والانصراف المبكر، والعمل الإضافي.
    - رسم يومي، وجدول لكل موظف، والمحاولات المرفوضة، والتصدير إلى Excel.
  - دور جديد **"موظف"** لمن يحتاج الحضور والإجازات فقط، ويُنشأ حسابه من ملف الموظف.
  - **حدود الحماية:**
    - التطبيق أصعب بكثير في التلاعب من المتصفح، فمن الإعدادات يمكن قصر التسجيل على التطبيق.
    - أدوات إخفاء الروت المتقدمة قد تتجاوز كشف الجهاز. لذلك يجمع النظام بين عدة طبقات (الجهاز المعتمد، والرمز، والدقة، والسجل)، ويُبقي كل شيء مسجلاً للمراجعة.
- **الموارد البشرية:**
  - **ملف الموظف:** البيانات الشخصية والوظيفية، العقد، الراتب والبدلات، الدوام وأيام الراحة، وربطه بحساب دخول.
  - **المستندات:** الهوية والإقامة والشهادة الصحية والعقود، مع إرفاق صورة أو PDF، وتنبيه قبل الانتهاء.
  - **الحضور والانصراف:** كل موظف يسجّل من حسابه، والتأخير يُحسب تلقائياً مع سماحية قابلة للضبط، والمدير يسجّل أو يعدّل يدوياً. يتوفر كشف يومي وملخص شهري.
  - **الإجازات:** سنوية ومرضية واضطرارية وبدون راتب، مع طلب واعتماد أو رفض، ورصيد سنوي.
  - **الرواتب:** مسير شهري بخصم الغياب والتأخير، مع المكافآت والخصومات والسلف، وقسيمة راتب قابلة للطباعة.
- **الأمان:** صلاحيات حسب الدور، تشفير كلمات المرور، JWT، سجل تدقيق لكل الإلغاءات والخصومات وتغيير الأسعار.
