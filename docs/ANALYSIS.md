# تحليل وتصميم نظام إدارة المطعم

## 1. الهدف
نظام يدير عمليات المطعم اليومية من استقبال الطلب حتى الدفع والتقارير، ويعمل على الشبكة المحلية للمطعم من أجهزة متعددة (كمبيوتر الكاشير، تابلت النادل، شاشة المطبخ) مع تحديث لحظي بينها.

## 2. المستخدمون والصلاحيات

| الدور | الصلاحيات |
|---|---|
| المدير العام | كل شيء، بما في ذلك إدارة المستخدمين وسجل التدقيق |
| مدير الفرع | قائمة الطعام، المخزون، الطاولات، الإعدادات، التقارير، الورديات، وكل عمليات البيع |
| الكاشير | إنشاء الطلبات، الدفع، الخصم، الإلغاء، الورديات، الحجوزات، العملاء |
| النادل | فتح الطاولات، أخذ الطلبات وإرسالها للمطبخ، التقديم، نقل الطاولة، الحجوزات |
| المطبخ | شاشة الطلبات وتحديث حالتها، إيقاف الأصناف النافدة، تسجيل الاستلام والتالف |

## 3. البنية التقنية

| الطبقة | التقنية | السبب |
|---|---|---|
| الخادم | Node.js 22 + Express 5 | خفيف، يعمل على أي جهاز ويندوز/لينكس في المطعم |
| قاعدة البيانات | SQLite (المدمجة في Node) | ملف واحد، لا تحتاج تثبيتاً أو إدارة، كافية لفرع واحد |
| التحديث اللحظي | Socket.io | شاشة المطبخ والطاولات تتحدث فوراً |
| المصادقة | JWT + bcrypt | جلسات آمنة بدون حالة على الخادم |
| الواجهة | React 19 + Vite | واجهة سريعة تعمل في المتصفح |
| التطبيق | Capacitor 8 (Android) | نفس الواجهة داخل تطبيق APK أصلي |

## 4. نموذج البيانات

```
users ─────────────┐
                   ├── orders ──┬── order_items ── menu_items ──┬── categories
dining_tables ─────┤            ├── payments                     ├── modifiers
customers ─────────┤            └── stock_movements              └── recipes ── ingredients
shifts ────────────┘
reservations ── dining_tables
settings · audit_log
```

| الجدول | الوصف |
|---|---|
| `users` | المستخدمون والأدوار |
| `categories`, `menu_items`, `modifiers` | قائمة الطعام والإضافات |
| `ingredients`, `recipes`, `stock_movements` | المخزون والوصفات وحركاته |
| `dining_tables`, `reservations` | الطاولات والحجوزات |
| `orders`, `order_items`, `payments` | الطلبات وأصنافها ودفعاتها |
| `customers` | العملاء ونقاط الولاء |
| `shifts` | ورديات الكاشير وجرد الصندوق |
| `settings` | إعدادات المطعم (الضريبة، الرسوم، العملة…) |
| `audit_log` | سجل كل العمليات الحساسة |

## 5. دورة حياة الطلب

```
            إنشاء                 إرسال للمطبخ          المطبخ               المطبخ             النادل
الصنف:   [pending] ───────────► [new] ─────────► [preparing] ─────────► [ready] ─────────► [served]
              │                    │
              └── إلغاء ──► (يُحذف)  └── إلغاء (كاشير/مدير) ──► [cancelled]

الطلب:   [open] ──── دفع كامل ───► [paid]   ← يُخصم المخزون حسب الوصفات + نقاط الولاء
            └────── إلغاء ───────► [cancelled]  (فقط إن لم تكن عليه دفعات)
```

## 6. قواعد العمل
1. الطاولة لا تحمل أكثر من طلب مفتوح واحد.
2. طلب التوصيل يتطلب رقم الجوال والعنوان، ويُنشأ العميل تلقائياً أو يُحدَّث.
3. لا يمكن تعديل كمية صنف أُرسل للمطبخ، ويحتاج إلغاؤه صلاحية كاشير أو مدير.
4. الباقي للعميل يُحسب من الدفع النقدي فقط، ولا يقبل النظام دفعاً بالبطاقة أكبر من المطلوب.
5. خصم المخزون يحدث عند إغلاق الطلب بالدفع، حسب وصفة كل صنف × الكمية.
6. استلام البضاعة بسعر جديد يحدّث تكلفة الوحدة بالمتوسط المرجّح.
7. الجرد يسجّل الفرق بين الرصيد الدفتري والفعلي كحركة تسوية.
8. الوردية: النقد المتوقع = النقد الافتتاحي + الدفعات النقدية في الوردية.
9. كل الإلغاءات والخصومات وتغيير الأسعار وفتح وإغلاق الورديات تُسجّل في سجل التدقيق.

## 7. المتطلبات غير الوظيفية المطبّقة
- واجهة عربية بالكامل (RTL) تتكيف من شاشة الجوال حتى شاشة المطبخ الكبيرة، مع وضع ليلي تلقائي.
- أزرار كبيرة مناسبة للمس (42px أو أكبر).
- إعادة الاتصال تلقائياً بالخادم مع مؤشر "متصل/غير متصل".
- المعاملات (transactions) لكل عملية متعددة الخطوات كالدفع والخصم من المخزون.
- اختبارات آلية لدورة الطلب الكاملة (`backend/test`).

## 8. مراحل التطوير القادمة (مقترحة)
- **تعدد الفروع:** إضافة `branch_id` للجداول ولوحة مركزية.
- **الطلب الذاتي:** رمز QR على الطاولة يفتح قائمة الطعام للعميل.
- **الفوترة الإلكترونية:** الربط مع ZATCA (رمز QR بصيغة TLV على الفاتورة).
- **الطباعة المباشرة:** طابعات ESC/POS عبر الشبكة لتذاكر المطبخ والفواتير بدون نافذة الطباعة.
- **الموردون وأوامر الشراء:** دورة شراء كاملة مع الذمم.
- **العمل دون اتصال:** تخزين الطلبات مؤقتاً على الجهاز ومزامنتها عند عودة الشبكة.
- **التكامل مع تطبيقات التوصيل.**
